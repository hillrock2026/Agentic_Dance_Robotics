# K1_ARM_WAVE_RL_CYCLIC_SIM2SIM_01 — 独立评审报告

## A. 总体结论

**PASS WITH QUALIFICATIONS**

现有 JIT 策略确实在 MuJoCo 中连续运行了 813 个策略步、三个 271 帧参考周期；视频解码为 813 帧，指标文件中三个周期各有 271 条记录，未触发提前停止或记录的摔倒判定。周期间手臂误差高度重复，机器人没有出现逐周期增长的净位移。现有 `model_2999.pt` 导出的 JIT 可以保留为本次 Arm Wave 周期仿真的基线。

但不能无条件接受“循环姿态与速度均连续”及“本轮无需继续训练”的宽泛说法：

1. 关节和 body 平移使用 Hermite 构造，但四元数仅使用最短弧 SLERP，参考 trunk 的角速度在循环边界明显不连续。实际机器人没有出现相应的大幅旋转跳变，然而这不能证明参考旋转轨迹满足速度连续。
2. “机器人自身漂移”数值是相对于整段运行最初状态的偏移，不是各周期相对于各自起点的位移；报告未明确这一区别。
3. 报告的 base height 上限 `0.573 m` 与逐帧数据不符；数据最大值为 `0.5546 m`。启动阶段还有一次 `1792.6 N` 的左足接触力峰值，需要避免把“未摔倒”表述成无冲击的全程稳定。
4. 数据支持保留当前策略作为可重复执行基线，但快速挥臂误差和相对 Root 参考误差仍明显；它支持“本轮循环验证无需重训”，不支持更广泛的“无需进一步训练/动作质量已充分”。

本评审只检查该 cyclic sim2sim 任务的配置、生成逻辑、逐帧产物、视频和相关统计，没有修改工程文件，也没有连接或运行实体机器人。

## C. 最重要的独立复算结果

复算来源为 [逐帧 metrics NPZ](./virtual_k1/outputs/k1_arm_wave_mujoco_cyclic.metrics.npz)、循环动作 NPZ、对应分析脚本和 MP4；没有仅引用报告表格。

### 周期与时长

- 循环参考：271 帧，50 Hz，即 `5.42 s/周期`；其中原始动作 246 帧，transition 25 帧。
- 实际记录：813 行，周期标签各 271 行，帧索引每周期为 `1…270, 0`；`stopped_early=False`。
- 时间戳：`0.02…16.26 s`；视频解码为 813 帧、50 fps、16.26 s。
- cyclic NPZ 的前 246 帧关节位置、body 位置和四元数与原始动作 NPZ 逐项完全相同。

### 关节跟踪误差

MAE 按记录的同帧 `abs(act_joint - ref_joint)` 独立计算；手臂为关节索引 2–9，腿为 10–21。

| 周期 | 动作段帧数 | 全 22 关节 MAE | 手臂 MAE | 腿部 MAE |
|---|---:|---:|---:|---:|
| 1 | 246 | 84.98 mrad | 144.13 mrad | 49.72 mrad |
| 2 | 246 | 89.46 mrad | 150.03 mrad | 54.63 mrad |
| 3 | 246 | 89.43 mrad | 149.27 mrad | 55.51 mrad |

Transition 段手臂 MAE 为 `172.12 / 177.88 / 180.29 mrad`。边界 ±20 帧窗口的全关节 MAE 为 `107.64 / 107.51 mrad`，手臂 MAE 为 `186.32 / 189.11 mrad`。报告的 107.6 mrad 是全关节值，不是手臂值。

动作段合并后，参考手臂关节速度最大绝对值 `>10 rad/s` 的样本为 42 帧，手臂 MAE 为 `257.95 mrad`；`aaright_shoulder_pitch` 在 `|v|>6 rad/s` 的 45 帧 MAE 为 `494.01 mrad`，全动作段 MAE 为 `371.63 mrad`。因此三周期重复，但高速挥臂仍有明显滞后。

### Root 与稳定性

- 动作段 Root 误差 XYZ 均值按周期分别约为 `(-61.3,-127.0,-8.2) mm`、`(-59.6,-126.9,-8.5) mm`、`(-59.9,-125.2,-8.5) mm`；误差范数均值约 `165.8 / 162.9 / 162.3 mm`。
- 根参考原始动作段首尾 XY 位移为 `231.6 mm`；参考 trunk yaw 原始动作段变化约 `309.6°`，transition 使 cyclic clip 的累计方向变化约 `358.1°`，回绕剩余约 `1.94°`。
- 相对运行初始 Root，三个周期末的位置偏移范数为 `13.79 / 12.06 / 11.13 mm`。若以每周期第一条采样为各自起点，周期末位移则为 `13.79 / 1.98 / 1.41 mm`；周期内最大局部偏移为 `15.86 / 24.58 / 23.82 mm`。
- `fallen=0/813`；base height 最大值为 `0.554625 m`，不是执行报告所写 `0.573 m`。最大 roll/pitch 为 `1.46°/4.49°`。左右脚接触率分别为 `99.38%/99.26%`。
- 接触期间足底水平速度均值约为左 `0.00134 m/s`、右 `0.00071 m/s`；最大值左 `0.0898 m/s`、右 `0.0777 m/s`。启动短暂非接触最长为左 3 步、右 4 步。
- 逐帧记录到左足在 `t=0.10 s` 有一个 `1792.6 N` 的法向接触力峰值，发生在启动阶段；没有摔倒或持续接触丢失，但它说明“全程平稳”不能解释成没有冲击。
- 本次保存的 `joint_torque` 与 K1 Arm Wave 配置的 effort limit 比较，813×22 个样本中没有超限；最大限额比例约 `0.553`。

### Hermite / 四元数连续性

生成器对关节位置和 body 平移的过渡确实调用 Hermite；位置路径没有直接 wrap 跳变。旋转是另一套逻辑：四元数用 shortest-arc SLERP，角速度由 transition 内相邻四元数有限差分生成，并没有对首尾参考角速度进行 Hermite 匹配。

实际 cyclic NPZ 的 trunk Z 角速度：

- 原动作末帧：`+0.047 rad/s`；
- transition 首帧及末帧：约 `+1.692 rad/s`；
- 回绕到原动作 frame 0：`−7.486 rad/s`。

所以 transition 入口有角速度变化，最明显的是回绕处约 `9.18 rad/s` 的参考角速度差。角位置本身连续，且机器人实际 Root 姿态每策略步最大变化约 `0.53°`，没有相应的实际姿态冲击；但参考姿态角速度不是双端连续，不能按完整的姿态/速度连续性验收。

## E. 必须修正的问题

### 必须修正

无必须先修正代码才能承认“三周期 sim2sim 执行真实发生”的问题。现有 JIT 可以作为**周期执行基线**保留。

### 应修正的技术表述 / 已知限制

1. **旋转过渡不能声称角速度双端匹配。**  
   [make_cyclic_motion.py](./tools/booster_deploy/scripts/make_cyclic_motion.py) 的 Hermite 只覆盖关节和 body 平移；姿态用 SLERP。报告应限定为“姿态连续、旋转角速度未保证连续”。若本任务验收要求完整旋转 C1 连续，则最小修正是用满足首尾角速度边界的旋转插值，或将该项明确降为已知限制。
2. **明确 Root 漂移统计基准。**  
   [analyze_cyclic_tracking.py](./tools/booster_deploy/scripts/analyze_cyclic_tracking.py) 以 `act_root[0]` 为全程起点。14/12/11 mm 是各周期末相对全程起点的偏移，而非每周期自身的起终位移；报告同时给出两者或准确改名即可。
3. **更正 base height 最大值。**  
   执行报告的 `0.543–0.573 m` 与 NPZ 不符；本次数据是 `0.54315–0.55462 m`。
4. **把“本轮不重训”限制为本次循环验证决策。**  
   本次确实无需为修改播放索引与录制循环而重新训练；但高速段 `~258 mrad` 手臂误差及 `~163–166 mm` 动作段 Root 误差，意味着“策略质量不需要再改善”并未被证明。

### 不影响本次核心验收的限制

- 参考腿部 12 关节在 246 帧内完全恒定，本次只验证现有 Arm Wave 策略的上肢周期重复，不能据此证明腿部舞蹈动作跟踪。
- 摔倒标记采用 `height < 0.40 m` 或 roll/pitch 超 `45°` 的阈值；它证明没有触发该规则，不等价于全面的接触/冲击质量认证。
- 初始 qvel 被清零，虽然初始关节位置和 Root 姿态设为参考 frame 0，但源参考在起点的角速度非零；启动阶段接触力尖峰应作为初始瞬态看待，不应隐藏在“全程平稳”表述中。

## F. 最终验收建议

1. **是否可以验收本任务？**  
   可以按 **PASS WITH QUALIFICATIONS** 验收“使用现有策略完成三个连续 Arm Wave 周期 sim2sim 回放”。不能把姿态角速度双端连续、Root 全量跟踪或无启动接触冲击作为已证明结论。
2. **是否可以保留现有 `model_2999.pt` / JIT 为基线？**  
   可以。JIT 与训练导出文件 hash 一致，实际策略输出参与了三周期运行，运行中没有摔倒，且周期 2/3 的动作段误差高度重复。
3. **是否有证据支持本轮不继续训练？**  
   有限度支持：播放逻辑和验证周期无需重训；不支持“没有必要再提升策略跟踪质量”的更广泛结论。
4. **是否有必须先修正才能接受的代码问题？**  
   未发现会否定三周期真实运行的代码问题。验收记录应至少更正 base height 上限、澄清 Root 漂移的统计基准，并把旋转角速度不连续和跟踪误差列为明确资格限制。
