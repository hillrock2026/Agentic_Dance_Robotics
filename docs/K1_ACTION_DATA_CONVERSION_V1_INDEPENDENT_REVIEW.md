# K1_ACTION_DATA_CONVERSION_V1 独立技术评审报告

评审日期：2026-11-16  
评审对象：Motion Studio SMPL 动作到 K1 22-DOF 动作数据转换、数据集与 Virtual K1 验证  
评审方式：只读检查与独立复算；未改代码、配置、原始数据或数据集

## A. 总体结论

**PARTIAL PASS**

转换包、映射、三条动作数据及其元数据/manifest 均真实存在；三条转换均可由所记录的 Motion Studio 输入确定性重建，测试和哈希也可复核。官方 K1 CSV 的列结构与根四元数顺序、22-DOF 名称映射、单位和关节限位总体成立。Arm Wave 的这次关节 PD 物理回放通过；Top Rock 与 Popping 的关节 PD 物理回放失败，且都如实标成 `NEEDS_REVIEW`。

不能接受执行报告中“三种动作均运动学回放 PASS”的结论：运动学回放对 box 足底仅检查几何中心高度，没有检查旋转后碰撞盒底面。独立按模型中的足底碰撞盒角点复算，**Top Rock 的足底在全部 286 帧中至少一侧穿过地面，最深约 58.4 mm**，而现有检查仍报告无穿透、A-pass。此外，小腿方向误差代码使用了“膝到脚尖”向量替代“膝到踝”向量，报告中的小腿误差统计不是目标定义的骨段误差。

因此：转换链路和数据产物成立，但核心验证存在足以改变动作有效性判断的实现缺陷。Top Rock 不能按当前证据称为通过运动学验证或已验证的 K1 训练样本；须先修正/重做相应验证，才能接受其当前通过结论。本评审不因物理 PD 回放失败直接否定转换算法，也不据此推断单一失败原因。

## C. 官方格式核验

### 官方 CSV 结构和数值

- **直接证据**：`k1_fight_001.csv` 有 707 行（含标题，即 706 条数据），`k1_mj2_seg1.csv` 有 1262 行（含标题，即 1261 条数据）；每个标题均为 29 列：Root 位置 3 列、Root 四元数 4 列、关节 22 列。
- **直接证据**：标题明确写为 `root_quat_x/y/z/w`。官方首帧四元数范数约 1。将首帧按 xyzw 转成 MuJoCo wxyz 做 `mj_forward()`，足底碰撞盒底面约高于地面 4.8 mm；把相同数值错误地按 wxyz 解释时，足底会升至约 0.63 m 以上。列名、数值和模型正向运动学共同支持官方 CSV 的 xyzw 解释。
- **直接证据**：官方 XML hinge 角度以弧度编译，CSV 关节数值可直接写入对应 qpos 复现相同 K1 关节姿态；关节顺序为头 2、左臂 4、右臂 4、左腿 6、右腿 6。XML/CSV 的名称差异只有左右 shoulder pitch 两列，映射配置逐一列出。
- “绝对弧度角”与 MuJoCo qpos 使用方式一致，模型关节限位也与输出角度量级一致；不过执行报告所说的“首帧逐位一致”不成立为严格相等：与当前 V1 站立关节配置比较，22 个关节均有非零差异，最大约 **0.001679 rad**。大多数差异是微小舍入量级；Root 世界坐标和平面朝向也不同（官方 CSV 首帧有非零 x/y 和 yaw，V1 初始位姿 root 置于原点朝向）。因此只能称为关节姿态近似对照，不能说所有 Root/关节值逐位一致。
- 官方 CSV 无时间戳/FPS 列。官方文件首帧或相邻帧变化本身不能证明其 FPS。

### 输出兼容性

- 输出标题实际为 `frame_index, timestamp_s` 后接官方 29 列；去掉这两列后，顺序和拼写与官方标题完全相同。
- 项目内部 `load_k1_action()` 是按列名的 CSV DictReader，可读取此格式；现有测试也只核对官方列子集顺序和内部 round-trip。
- **未验证**：没有找到/运行真实官方 CSV 消费程序对 31 列输出的集成读取。按名称读并容忍额外列的程序可能兼容；按固定 29 列位置读取的程序会把前两列错当成 Root 数据。故“官方兼容”应限定为“官方 29 列子集保留”，不能声称已验证任意官方读取工具直接兼容。

## D. Human-to-K1 重定向核验

### 坐标与 IK

- **代码证据**：坐标代码使用人体左肩线、K1 左右肩连线和固定重力方向构造躯干框架；SMPL joint ID 来自明确配置，而非扫描名称猜轴。K1 与人体的上方向映到各自定义坐标。
- **直接证据**：已有自动测试检查 `R.T @ R = I`、正手性及 MS_WORLD 的 `+Y` 映到 K1 `+Z`。输出 CSV 中的左右侧关节列按明确别名映射。独立用 K1 躯干局部坐标检查三条输出，左右肘侧在全部输出帧均符合各自左右侧。
- **代码证据**：肩/髋/膝/踝链按配置取人体骨段单位方向目标，MuJoCo `mj_jac` 计算位置雅可比，使用阻尼最小二乘迭代，关节值每步受 XML 限位与 margin 限制。帧间以前一帧角度作为初始解，之后做五帧滑动平均。
- **独立方向误差复核**：从实际输入的 joint_positions 对齐到输出时间，再用输出 qpos 及 MuJoCo 几何计算骨段方向。上臂、大腿中位值可复现到约 0.1° 内；这只说明特定骨段方向误差，**不等于关节角参考误差、全身姿态误差或动力学可执行性**。多个均值明显大于中位数，例如上臂 mean：Arm Wave 16.37°、Top Rock 11.77°、Popping 10.45°，所以用 2–6° 中位数概括成“精确”会隐藏较大误差尾部。

### 方向误差实现错误

`retargeting.py` 的 `_measure_quality()` 对腿部计算 `gs = (toe - knee)`，并将它与人体 **knee→ankle** 小腿方向比较；正确 K1 小腿骨段应为 knee-anchor→ankle-anchor。脚段再另行使用 toe−ankle。独立按正确端点复算，已交付报告中的小腿中位误差与目标定义不匹配：

| 动作 | validation 中报告的小腿中位方向误差 | 正确 knee→ankle 端点复算 |
|---|---:|---:|
| Arm Wave | 31.18° | 约 15.85° |
| Top Rock | 27.45° | 约 19.11° |
| Popping | 30.37° | 约 19.54° |

这是段方向质量指标实现缺陷；不能拿报告中的小腿数字作准确度结论。它不直接改写输出关节 CSV，但影响重定向质量声明和对照算法表现的判断。

### 49° 下肢噪声与双模式

- `49°` 在执行报告及 README 中出现，但未找到可复现的计算脚本、具体测量关节、帧段、统计定义或对应结果文件。无法确认它是关节角漂移、骨段方向误差还是其他指标，结论标为 **UNVERIFIED**。编辑 NPZ 的接触信息明确为高度/速度/滞回几何估计，不能拿它作为物理接触测量支持 49°。
- **代码证据**：`upper_body_mode` 只求解头和两臂，随后把 12 个 K1 腿部关节固定到其官方姿态，并固定 root z。它确实隔离了腿部关节角，但 root 的 x/y 和 yaw 仍由人体 pelvis/global-orient 推出，故并未冻结所有下肢相关的基座运动。
- 该模式是可接受的**局部工程策略**，前提是数据语义明确为上肢动作、腿部固定，不可称为完整忠实全身重定向。当前 metadata 的 mode 描述有记录；腿部质量指标仍保留较高误差，没有被伪装成完整匹配。

## E. 三种动作逐项评审

共同说明：格式/限位结果来自真实 CSV 和 XML；A 是直接设置输出 Root/关节 qpos 后的运动学正向计算，不是物理步进；B 是从 V1 初始站立位出发的关节 PD 回放。

### Arm Wave

- **格式**：246 帧、50 Hz、`frame_index + timestamp_s + 官方 29 列`，duration 4.92 s；四元数范数范围约 `0.9999999994–1.0000000007`。22 关节无越限。
- **运动学与方向**：输出可复现；左右上臂中位方向误差约 5.83°，均值约 16.37°。前臂/脚方向误差较大；小腿报告误差受上述端点 bug 影响。
- **Root/足地**：Root z 固定在官方 CSV 首帧约 0.555 m。现有 A 记录的 `ground_penetration_min_m=+0.0233 m` 实为几何中心高度式指标；按旋转后的足底 box 角点算，最低点约高于地面 **4.7 mm**，246 帧均未发生几何接触（`mj_forward` 无足-地 contact），是小间隙而非穿透，也不能称已证明 A 中有接触。
- **速度/加速度**：独立对 50 Hz CSV 差分，左 shoulder pitch 峰值约 **15.35 rad/s、391.52 rad/s²**；右侧约 **9.79 rad/s、204.46 rad/s²**。其验证配置阈值为 8 rad/s、200 rad/s²。执行报告只强调速度，validation 的 `dynamics.pass` 实际同时因速度和加速度超阈值为 false；`needs_review` 字符串漏列了加速度原因。项目/模型中未找到可信 K1 电机额定速度，故速度是否可接受为 **UNVERIFIED**，保留 NEEDS_REVIEW 合理。
- **物理回放**：独立重跑未跌倒，Root z 约 0.5466–0.5510 m。JSON 的 `tracking_rmse_rad=0.0227` 实际是每个采样时刻 22 关节 RMSE 的算术平均，比较的是滤波后的目标（`q_filt`），包括 hold/ramp 等阶段；不是覆盖纯动作轨迹的全元素 RMS。接触吻合是与 Motion Studio 估计接触比较（左 99.2%、右 71.1%），不是独立测得的地面真值。
- **状态/训练价值**：metadata、validation、manifest 均为 NEEDS_REVIEW，理由至少包含速度/加速度阈值问题；物理 PASS 仅说明该次指定 PD、初始状态和条件下未跌倒。是**上肢主导候选动作**，不是通过硬件速度验收的可直接执行数据。

### Top Rock

- **格式/关节**：286 帧、50 Hz、5.72 s；输出关节限位检查通过，validation 的速度/加速度检查也通过（相对项目软件阈值），SHA256 一致。人输入的 `time_scale=0.7` 有编辑日志记录，143 帧@25 Hz 输入。
- **运动学**：当前实现判 A-pass，报告 `ground_penetration_min_m=+0.00286 m`；但该数值是 Box 的 geom 中心 z，不是底面高度。直接用 K1 足底碰撞盒的 8 个旋转角点复算，**286 帧每帧至少一只脚底低于地面；最大穿透约 58.4 mm**。正向计算产生的足-地 geom 接触覆盖 225/286 帧。A-pass 因而是验证器漏检，不能接受为“无穿透”的运动学通过。
- **方向/root**：上臂、大腿中位方向误差分别约 2.12° / 0.325°，但 mean 为 11.77° / 0.517°；小腿误差按正确端点约 19.11°，不是报告的 27.45°。Root xyz/朝向是启发式人体重定向结果；固定髋高和躯干 yaw 近似不能保证脚底几何可行。
- **物理回放**：独立重跑 B-fail，Root z 最低约 **0.0599 m**。B 的实现只对 22 个关节作滤波 PD 目标，Root 保持物理自由状态；它**没有把输出 CSV 中 root_pos/root_quat 回放进模型**。因此该结果是该控制方式下的关节回放失败，不是对 31 列完整动作的根轨迹动力学验证，也不足以单独归因于特定原因。
- **状态/训练价值**：manifest/metadata/validation 均为 NEEDS_REVIEW，物理失败有记录。但“格式+限位+运动学检查全部通过”不成立；在当前足底穿透问题复核前，不能称为 K1 运动学有效或已验证训练样本。最多是**可复现的人体重定向候选轨迹**，不等同 K1 可执行动作。

### Popping

- **格式/关节**：243 帧、50 Hz，metadata duration 4.86 s；22 关节没有越 XML 限位。源为 146 帧@30 Hz、duration 4.8666667 s，输出比源短约 **6.67 ms**。
- **运动学**：A 当前判 PASS；正确角点复算没有地面穿透，但 243 帧在 `mj_forward` 中没有足-地 contact。最低角点距地约 1.35 mm（左）/2.58 mm（右），最高角点达约 0.134/0.237 m。是否合理取决于动作腾空/接触语义；当前 A 并未实际验证接触，源接触又只是人体估计。
- **快速特征/平滑**：输出仍有约 **0.36 rad** 最大帧间跳变、右肩速度约 **17.95 rad/s**、加速度约 **521.29 rad/s²**，超出当前软件阈值。重定向先在 30 Hz 序列上做 5 帧滑动平均（窗口约 167 ms），之后升采样到 50 Hz；没有原始动作与输出快速收缩/释放特征保留的比较指标，故无法确认快动作特征被准确保留。存在高速度/高加速度，不等同已经证明硬件不可执行；额定速度无证据。
- **物理回放**：独立重跑 B-fail，Root z 最低约 **0.0600 m**；与 Top Rock 一样，只施加关节目标，不播放输出 Root 轨迹，不能据此作完整 Root 动力学判断。
- **状态/训练价值**：NEEDS_REVIEW 正确且与高速度、加速度、帧跳变和 B-fail 对应；可作为待审阅转换候选，不应称为已验证 K1 动作/训练样本。快速局部动作的忠实程度尚未证明。

## F. 时间轴和数值质量

### 独立时间轴复算

| 动作 | 输入帧/FPS/源 duration | 输出帧/FPS/导出 duration | 输出首末时间戳 | 复核 |
|---|---|---|---|---|
| Arm Wave | 123 / 25 / 4.92 s | 246 / 50 / 4.92 s | 0.00–4.90 s | duration 按帧数/FPS 定义；源末采样时间 4.88 s，最后目标采样落在源末点之后并由 `np.interp` 端点保持 |
| Top Rock | 143 / 25 / 5.72 s | 286 / 50 / 5.72 s | 0.00–5.70 s | duration 按帧数/FPS 一致；末目标采样比源末采样时间 5.68 s 多 20 ms，端点保持 |
| Popping | 146 / 30 / 4.866667 s | 243 / 50 / 4.86 s | 0.00–4.84 s | 舍入目标帧数导致 duration 短 6.667 ms；末输出时间超源末采样 6.667 ms，使用端点保持 |

`resample()` 用 `round(T*new_fps/old_fps)` 选帧数，统一 25→50 的两个动作恰好整倍数，因而测试没有暴露 30→50 的量化差异。当前时间戳是等间隔 `1/fps`；duration 语义采用 `frame_count/fps`，不是首末样点时间差。报告“时长精确保留”对 Popping 不成立，应改成有界近似或采用明确端点方案。

### 其他数值核验

- 输出 31 列，去掉新增的两列后，29 个官方列名/顺序匹配。
- 三个输出 root 四元数范数约为 `0.9999999994–1.0000000007`。SLERP 实现归一化输入/输出并按点积翻转符号走最短弧；这一点由代码及输出数值支持。
- 22 个关节无 XML 行程越界。速度/加速度独立从 50 Hz CSV 重新差分，与保存统计的主要峰值一致。
- CSV 的 9 位关节/Root 数值和 6 位时间戳足以复现当前数值；原始输入 SHA256、三份轨迹 SHA256 及 metadata SHA256 均与 manifest/metadata 中对应值相符。
- “官方首帧逐位一致”应改为近似关节姿态比较；最大关节差约 0.001679 rad，Root 世界坐标及朝向并不相等。

## H. 问题清单

### 1. MAJOR — 运动学回放漏检足底穿透，Top Rock A-pass 不可信

- **位置**：[virtual_k1_replay.py](../k1_action/virtual_k1_replay.py#L53)
- **直接证据**：box geom（MuJoCo 类型 6）走 `else`，只取 `geom_xpos.z`；没有按 `geom_xmat` 和 box 半尺寸计算底面角点。Top Rock validation 因 geom 中心高度 `+0.00286 m` 判通过；独立按旋转 box 角点复算，286 帧中每帧至少一只脚穿地，最大约 `58.4 mm`。
- **影响**：执行报告的 Top Rock 运动学 PASS 和“地面无穿透”结论错误；相应轨迹不是已通过当前几何可执行性验收的数据。
- **总体影响**：是，直接影响关键验证项；促成总评 PARTIAL PASS。
- **最小建议**：用 MuJoCo 实际 collision geometry 的 support distance/接触距离或变换后的足底 box 角点检查；在此检查修正并重跑三条动作 A 验证前，不接受旧 A-pass。

### 2. MAJOR — 小腿方向误差用错 K1 骨段端点

- **位置**：[retargeting.py](../k1_action/retargeting.py#L465)
- **直接证据**：`gs`/`gf` 都是 `(toe-knee)`，但目标 `ts` 是人体 knee→ankle。独立端点复算三条动作正确小腿误差约 15.85°/19.11°/19.54°，与 metadata 中 31.18°/27.45°/30.37° 不符。
- **影响**：小腿方向质量表和算法精度论述无效；不能用其评价重定向精度。并非完整姿态误差指标。
- **总体影响**：影响报告准确性和质量验收，但不改变输出 CSV 现有数值。
- **最小建议**：小腿方向使用 knee-anchor→ankle-anchor，脚方向使用 ankle-anchor→toe；重新计算 metadata 与报告中的方向统计。

### 3. MINOR — Resample 帧数取整导致 Popping duration 不守恒

- **位置**：[trajectory_processing.py](../k1_action/trajectory_processing.py#L20)
- **直接证据**：146 帧@30 Hz 的 4.8666667 s 转成 243 帧@50 Hz、4.86 s，差 6.667 ms；现有 resample 测试只用 25→50 的整倍数 Arm Wave。
- **影响**：端点时间/持续时间在非整倍数采样率下有小量量化并端点保持；不改变关节/Root 列格式，但“精确保留 duration”过强。
- **总体影响**：否，局部时间语义精度问题。
- **最小建议**：明确目标是保时长还是保固定间隔/帧数；为 30→50 等非整倍数增加端点断言。

### 4. MINOR — validation 的加速度超阈值原因未写入 needs_review

- **位置**：[validators.py](../k1_action/validators.py#L64)
- **直接证据**：Arm Wave 的 dynamics 报告超过 200 rad/s²（肩部约 391.5、204.5）；Popping 约 351.8、521.3。`dynamics.pass=false`，但 `needs_review` 只追加帧跳变/速度消息，没有加速度消息。执行报告说 Arm Wave NEEDS_REVIEW“仅因肩速”不准确。
- **影响**：当前 status 仍保守地保持 NEEDS_REVIEW；只是人工复核原因遗漏，可能漏掉动作急动风险。
- **总体影响**：否，状态没有被错误升级。
- **最小建议**：将 `jerky` 关节及加速度数值写入 needs_review，并在报告列出。

### 5. MINOR — “官方兼容”没有真实官方读取器验证

- **位置**：[skeleton_mapping.py](../k1_action/skeleton_mapping.py#L40)、[action_exporter.py](../k1_action/action_exporter.py#L30)
- **直接证据**：输出在官方 29 列前新增两列；测试只过滤这两列再比较标题，并用项目自己的 DictReader round-trip。仓库中未发现官方读取程序对该 31 列文件的集成测试。
- **影响**：名称型读取可能兼容，但位置型/严格 29 列读取器会错读或拒绝；当前不能作普遍兼容保证。
- **总体影响**：否，项目内部读取可用。
- **最小建议**：报告收窄为“官方列子集兼容”；如要求官方读取器直接使用，应导出独立 29 列 CSV 或对真实消费者做集成验证。

### 6. OBSERVATION — `49°` 下肢噪声数字不可复现

- **位置**：[K1_ACTION_DATA_CONVERSION_V1_REPORT.md](./K1_ACTION_DATA_CONVERSION_V1_REPORT.md#L42)、[README.md](../k1_action/docs/README.md#L64)
- **直接证据**：代码/validation/输入 metadata 中未找到定义该角度统计的计算方法、关节、帧区间或原始结果；NPZ 仅标明几何估计接触。双模式实现本身可直接观察到固定 12 个腿部关节。
- **影响**：模式的动机“49° 超出 PD 能力”不能独立确认；但模式被明确记为 upper-body-only，腿部数据语义没有隐瞒。
- **总体影响**：不推翻模式实现；该数值保持 UNVERIFIED。
- **最小建议**：为该数字附上可复算定义/数据，或在报告中标成未验证估计。

### 7. OBSERVATION — B 物理回放不是完整 31 列 Root+关节轨迹回放

- **位置**：[virtual_k1_replay.py](../k1_action/virtual_k1_replay.py#L90)
- **直接证据**：B 从 `K1Sim()` 默认站立状态开始，只将 22 个关节目标交给 PD；循环不应用 trajectory 的 `root_pos/root_quat`。Root 自由受重力，跌倒阈值据此判断。Root 近似非动力学可行的限制有被报告记录。
- **影响**：A 与 B 验证对象不同；B-fail 表示该关节 PD 设置下跌倒，不能独立判定完整输入 Root 轨迹原因；B-pass 也不能证明整条 Root 轨迹可执行。
- **总体影响**：否，报告已有部分限定；但“物理验证”应精确表述为“关节 PD 自由 Root 回放”。
- **最小建议**：报告中明确写明 replay 忽略输出 Root 位姿，避免把 B 泛化成完整轨迹物理验证。

### 8. OBSERVATION — 物理回放“tracking_rmse”是滤波误差平均且含非动作阶段

- **位置**：[virtual_k1_replay.py](../k1_action/virtual_k1_replay.py#L101)
- **直接证据**：记录的是每个采样时刻对 22 个关节 `sqrt(mean(error²))`，最终对这些时刻指标取 `mean`；目标使用低通 q_filt，并包含初始 hold、ramp 和结束 hold。
- **影响**：0.023 rad 不是纯动作阶段、原轨迹目标的全元素 RMSE，作为动作跟踪精度数字会偏乐观/语义不明确。
- **总体影响**：否；Arm Wave “未跌倒”判定独立于该误差指标。
- **最小建议**：只在动作区间比较原始轨迹目标，并明确报告统计定义及峰值误差。

## I. 最终判定

1. **本次任务是否完成？**  
   转换工具、映射配置、三条数据集动作及数据集元数据已实现并可复现；但当前运动学验证存在会漏检显著地面穿透的问题，故本任务只能判为 **PARTIAL PASS**，不能接受“所有运动学回放 PASS”的总体主张。

2. **哪些动作已获得运动学验证？**  
   三条均运行了 A 正向运动学并得到现存结果，但该验证器足底盒检测有缺陷。Arm Wave 没有地面穿透但有约 4.7 mm 几何间隙；Popping 没有穿透，但此运动学回放中未形成足地 contact。**Top Rock 的 A-pass 已被独立复算推翻**，足底最大穿透约 58.4 mm。故现阶段不能把三条一概称为“已通过运动学验证”。

3. **哪些动作已经获得物理回放验证？**  
   三条均有独立复跑的关节 PD/自由 Root 回放：Arm Wave 未跌倒；Top Rock 与 Popping 跌倒。此 B 回放未施加导出 Root 轨迹，结论仅限当前关节 PD 回放条件。

4. **哪些动作只能称为转换后的候选数据？**  
   Top Rock、Popping 均为转换候选，均 NEEDS_REVIEW；Top Rock 当前还有实测足底穿地。Arm Wave 是上肢主导、腿部固定的候选；此次物理回放通过，但速度/加速度阈值仍未过，不能宣称已完成执行器速度验收。

5. **哪些数据尚需人工判定？**  
   三动作肩部速度阈值是否符合真实 K1 执行器额定速度（项目无可信额定速度证据）；Arm Wave/Popping 加速度与快动作质量；GVHMR `49°` 的定义/证据；Top Rock 穿地修正后的几何与接触；任何动作的 Root 动力学可行性。

6. **是否需要局部修复才能接受交付？**  
   若仅接受“生成了可复现的动作转换候选数据”，交付物真实存在且可复现；若接受报告中的 Top Rock 运动学通过及三动作方向质量数字，则需要局部修正/重算运动学足底检测与小腿方向误差，并更新相应 validation/metadata/报告后再判定。当前不需要推翻整个转换链路，但不能以现有 A-pass 结果验收 Top Rock。
